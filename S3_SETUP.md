# Настройка S3 хранилища для базы данных

## Проблема
Файлы базы данных (*.db, *.sqlite) исключены из репозитория через `.gitignore` и `.dockerignore`, поэтому данные не сохраняются при деплое на сервер.

## Решение
Используем S3-хранилище Timeweb для хранения файла базы данных. При запуске контейнера база загружается из S3 в том Docker volume.

## Изменения в проекте

### 1. Новые файлы:
- `entrypoint.sh` - скрипт загрузки базы из S3 перед запуском приложения
- `.env.example` - шаблон переменных окружения

### 2. Обновленные файлы:
- `Dockerfile` - добавлен aws-cli и entrypoint скрипт
- `docker-compose.yml` - добавлены переменные S3 и изменен путь к БД
- `.env` - добавлены параметры S3 (замените ключи на реальные!)

### Шаг 2: Обновите .env файл
Замените значения ключей в файле `.env` на реальные:
```
S3_ACCESS_KEY=ваш_реальный_ключ
S3_SECRET_KEY=ваш_реальный_секретный_ключ
```

### Шаг 3: Запустите контейнер
```bash
docker-compose up -d --build
```

## Как это работает

1. При старте контейнера выполняется `entrypoint.sh`
2. Скрипт проверяет наличие параметров S3
3. Если параметры указаны, скачивает базу из S3 в `/data/construction.db`
4. Запускается основное приложение
5. Все изменения в базе сохраняются в volume `cm_data`

## Важно!

- Файл `.env` с реальными ключами НЕ должен попадать в Git (он уже в `.gitignore`)
- Для продакшена используйте secrets management (Docker secrets, Vault и т.д.)
- При первом запуске без базы в S3 будет создана новая пустая база

## Переменные окружения

| Переменная | Описание | Значение по умолчанию |
|------------|----------|----------------------|
| S3_ENDPOINT | URL S3 сервиса | https://s3.twcstorage.ru |
| S3_BUCKET | Имя бакета | (требуется) |
| S3_ACCESS_KEY | Ключ доступа | (требуется) |
| S3_SECRET_KEY | Секретный ключ | (требуется) |
| S3_REGION | Регион | ru-1 |
| DB_FILE_NAME | Имя файла БД в S3 | construction.db |
| DB_PATH | Путь к БД в контейнере | /data/construction.db |
